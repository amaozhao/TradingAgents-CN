# 大语言模型对比与选择（AGENTrader 适配版）

**分类**: 模型选择指南
**难度**: 进阶
**阅读时间**: 15 分钟
**更新日期**: 2026-06-05

---

## 0. 总览

AGENTrader 的模型选择不应该只看“哪个模型最强”。股票分析是工具密集型任务，更重要的是模型能否稳定完成以下工作：

1. 正确理解股票、市场、日期、币种和数据源。
2. 稳定调用行情、财报、新闻、缓存和报告工具。
3. 在多智能体流程里遵守输出格式，方便后续智能体继续处理。
4. 在可接受成本内完成分析。

推荐把模型分成两类使用：

- **快速分析模型**：负责摘要、单一维度分析、批量扫描、新闻初筛。
- **深度分析模型**：负责多报告综合、多空辩论、风险裁决、最终报告。

具体模型名称、价格、上下文长度会随供应商更新而变化，应以“设置 → 配置管理 → 大模型配置”和供应商官网为准。

---

## 1. 选型三问

### 1. 推理够不够？

如果任务只是“总结新闻、提取财务指标、解释一个技术指标”，快速模型通常够用。

如果任务需要“综合多份报告、识别矛盾、平衡风险收益、输出最终结论”，应使用深度模型。

### 2. 工具调用稳不稳？

AGENTrader 的分析质量高度依赖工具调用。模型需要能稳定输出结构化参数，例如：

```json
{
  "symbol": "000001",
  "market": "CN",
  "date_range": "latest",
  "include_news": true
}
```

如果模型经常漏字段、把日期写错、把 A 股代码识别成美股代码，分析链路就会变慢甚至失败。

### 3. 成本能不能接受？

深度模型更稳，但每次分析的 token 消耗更高。常见做法是：

- 日常监控：快速模型。
- 重要单股：快速模型做初筛，深度模型做最终裁决。
- 批量任务：降低分析深度，限制输出长度，复用缓存。

---

## 2. 快速模型 vs 深度模型

| 维度 | 快速分析模型 | 深度分析模型 |
|------|--------------|--------------|
| 适用任务 | 摘要、初筛、单指标解释 | 综合判断、多轮辩论、风险裁决 |
| 成本 | 低 | 中到高 |
| 响应速度 | 快 | 较慢 |
| 上下文需求 | 中等 | 更长 |
| 输出要求 | 简洁、稳定 | 完整、可解释、格式严格 |
| 推荐温度 | 0.2-0.3 | 0.1-0.2 |

### 快速分析模型适合

- 市场新闻摘要
- 技术指标解释
- 财务指标初筛
- 自选股批量扫描
- 生成简短观察结论

### 深度分析模型适合

- 单股完整研究报告
- 多智能体多空辩论
- 风险团队裁决
- 重大事件复盘
- 长公告、长财报、长研报整理

## 3. AGENTrader 中的配置建议

### 常规配置

```yaml
快速分析模型:
  用途: 分析师、新闻摘要、批量筛选
  temperature: 0.2
  max_tokens: 800-2000

深度分析模型:
  用途: 研究经理、风险经理、最终报告
  temperature: 0.1
  max_tokens: 3000-8000
```

### 按场景选择

| 场景 | 建议 |
|------|------|
| 盘中快速看一只股票 | 快速模型，低输出长度 |
| 财报季做单股深度分析 | 深度模型，保留更长上下文 |
| 批量筛选几十只股票 | 快速模型 + 缓存 + 限制输出 |
| 重大事件后复盘 | 快速模型整理材料，深度模型综合判断 |
| 需要严格 JSON/工具调用 | 优先选择工具调用稳定的模型 |

---

## 4. 参数设置建议

| 参数 | 建议 | 原因 |
|------|------|------|
| temperature | 快速 0.2-0.3，深度 0.1-0.2 | 股票分析需要稳定，不需要太发散 |
| top_p | 默认即可，必要时 0.85-0.95 | 避免过度压缩表达 |
| max_tokens | 快速 800-2000，深度 3000-8000 | 防止报告中途截断 |
| timeout | 深度分析设置更长 | 工具调用和长报告会增加耗时 |
| retry_times | 建议开启 | 工具调用失败时可自动重试 |

不要为了“看起来更聪明”把 temperature 调高。高温度更适合创意写作，不适合财务数字和风控结论。

---

## 5. 常见踩坑

| 问题 | 表现 | 处理方式 |
|------|------|----------|
| 字段缺失 | 工具调用参数少了市场或日期 | 启用重试，使用更稳的模型 |
| 市场识别错误 | 把 000001 识别成美股代码 | 提示词中明确 market=CN |
| 数字幻觉 | 编造 PE、ROE、净利润 | 强制引用工具返回值 |
| 报告截断 | 最终结论缺失 | 提高 max_tokens |
| 成本过高 | 批量任务 token 暴涨 | 降低深度，复用缓存 |
| 输出格式漂移 | JSON/Markdown 不符合要求 | 降低 temperature，增加格式约束 |

## 6. 不同供应商怎么选？

### 国内网络优先

优先选择国内可稳定访问、工具调用表现稳定、费用可控的模型供应商。适合日常分析、批量任务和生产环境。

### 国际模型作为补充

国际模型通常在复杂推理、长上下文、多模态方面有优势，但可能受到网络、账号、费用和合规限制。适合作为备用或高价值深度分析模型。

### 本地模型

本地模型适合隐私敏感、离线实验或成本可控的场景，但需要自己承担部署、推理速度、上下文长度和工具调用适配成本。

---

## 7. 最终建议

1. 先配置一个稳定的快速模型，保证日常分析可用。
2. 再配置一个深度模型，用于研究经理、风险经理和最终报告。
3. 不要把模型名称和价格写死在判断里，定期到供应商官网核对。
4. 重要分析要关注数据源、工具调用和风险提示，不要只看模型输出是否流畅。
5. 如果结果不稳定，优先检查工具参数、提示词和数据源，再考虑更换模型。
